# Humidity Controller для Home Assistant

[![hacs_badge](https://img.shields.io/badge/HACS-Custom-orange.svg)](https://github.com/hacs/integration)
[![Validate](https://github.com/smart-ha/humidity-controller/actions/workflows/validate.yml/badge.svg)](https://github.com/smart-ha/humidity-controller/actions/workflows/validate.yml)

Кастомная интеграция: одна сущность `humidifier` на зону держит влажность по
**вашим** датчикам (одному или нескольким), управляя любым набором
увлажнителей (`humidifier.*`), розеток и `input_boolean`. Аналог
[climate-controller](https://github.com/smart-ha/climate-controller), только
для влажности. Всё настраивается в UI.

Писалась под Tion Iris через локальную интеграцию
[airmx](https://github.com/dext0r/airmx): Iris штатно держит влажность по
своему выносному датчику, а здесь — по датчикам, которые выберете вы.

## Возможности

- **Одна запись = одна зона = одна сущность `humidifier`** (device class
  `humidifier`): вкл/выкл, целевая влажность, текущая (сводная) влажность,
  `action` = `humidifying` / `idle` / `off`.
- **Несколько датчиков** со сведением `mean` / `min` / `max` / `median`.
  Недоступные датчики пропускаются, тик пропускается, только если выпали все.
  Показания каждого датчика — в атрибуте `humidity_readings`.
- **Пресеты** (`mode` сущности): свои названия, у каждого — влажность по
  умолчанию и расписание по времени суток (точки `время → влажность`, линейная
  интерполяция, через полночь). Новая запись начинается с `normal` / `sleep` /
  `away`. Режим `none` — «без пресета»: ручная установка влажности переключает
  на него.
- **Три способа управления увлажнителем** — выбираются для каждого устройства:
  - **Уставка** (по умолчанию). Устройство в своём режиме `auto`, ему
    отправляется цель с поправкой на разницу его показаний и наших:
    `цель + (влажность устройства − сводная влажность)`, поправка не больше
    `max_delta` (по умолчанию 10 %). Устройство регулирует само, но
    останавливается, когда до цели дошли *наши* датчики.
  - **Скорость.** Устройство в `manual`, скорость вентилятора (`number.*`,
    у Iris 0–100 %) — по дефициту влажности, PI-регулятор с границами
    min/max %. Включается при `цель − гистерезис`, выключается при
    достижении цели.
  - **Вкл/выкл** по гистерезису с минимальным временем работы и простоя.
    Единственный способ для `switch` / `input_boolean`.

  Если у увлажнителя нет нужного режима (`auto` для уставки, `manual` для
  скорости) или не выбрана / недоступна сущность скорости — устройство
  управляется вкл/выкл. Фактический способ виден в атрибуте `devices`.
- **Защита.** Если ни один датчик не даёт показаний дольше N минут
  (по умолчанию 15) — устройства в безопасное состояние: **выключить** или
  **отдать увлажнителю его собственный авторежим** с целевой влажностью без
  поправки (выключатели при этом выключаются). Вернулись показания — обычная
  регулировка.
- **Восстановление состояния** после перезапуска HA (вкл/выкл, режим, цель).

## Установка

### Через HACS

1. HACS → ⋮ → **Custom repositories** → `https://github.com/smart-ha/humidity-controller`,
   категория **Integration**.
2. Найдите **Humidity Controller**, нажмите **Download**, перезапустите HA.
3. **Настройки → Устройства и службы → Добавить интеграцию → Humidity Controller**.

### Вручную

Скопируйте `custom_components/humidity_controller/` в
`/config/custom_components/humidity_controller/` и перезапустите HA.

## Настройка

**Добавление записи** — название зоны, датчики влажности (`sensor` с
device class `humidity` или `input_number`), способ сведения, устройства.
Запись создаётся выключенной.

**Настроить** (OptionsFlow) — меню; изменения сохраняются только кнопкой
«Сохранить и выйти», закрыть окно = отмена:

| Экран | Что в нём |
|---|---|
| Датчики и защита | название, датчики, сведение, таймаут показаний (мин), безопасное состояние (выключить / авторежим устройства) |
| Устройства | список устройств с их способом; «Добавить / убрать устройства»; по нажатию на увлажнитель — его настройки: способ (уставка / скорость / вкл-выкл), макс. поправка уставки, сущность скорости, мин./макс. скорость, Kp, Ki |
| Гистерезис и время вкл/выкл | гистерезис (%RH), минимальное время работы и простоя (мин) — для способов «скорость» и «вкл/выкл» |
| Пресеты и расписания | список пресетов; «Новый пресет»; у пресета — название и влажность по умолчанию, добавить точку, редактировать расписание (с удалением строк), удалить пресет |

### Пример: Iris через airmx

Устройство `humidifier.a3s_v2_XXXXX`. Для способа «Скорость» выберите
сущность `number.a3s_v2_XXXXX_fan_speed`. Для «Уставки» дополнительная
сущность не нужна: используется `current_humidity` самого увлажнителя (у Iris
это выносной датчик, если он на связи, иначе встроенный).

## Как работает

Цикл — по изменению любого датчика и раз в 30 с:

1. Сводная влажность по доступным датчикам. Нет ни одного показания — тик
   пропускается (устройства остаются как были), а после таймаута — защита.
2. Цель: у активного пресета — точка расписания на текущее время, без
   расписания — его влажность по умолчанию; у `none` — заданная вручную.
3. Каждое устройство — своим способом. Команды отправляются, только если
   состояние устройства отличается от нужного; уставка переотправляется не
   чаще раза в минуту (сразу — если изменилась на 3 % и больше), скорость —
   при изменении на 5 % и больше или на границе диапазона.

Выключение сущности выключает все устройства; пока она выключена, устройства
не трогаются. Включённая сущность каждые 30 с возвращает устройства в нужное
состояние, даже если их переключили вручную.

### Атрибуты

- `humidity_readings` — `{датчик: значение или null}`;
- `humidity_sensors_unavailable` — недоступные датчики;
- `humidity_aggregation` — способ сведения;
- `failsafe` — `true`, пока действует защита;
- `devices` — по устройству: фактический способ, работает ли, отправленная
  уставка / скорость, собственная влажность устройства.

## Разработка

```bash
python -m py_compile custom_components/humidity_controller/*.py
python -m pytest -q
```

Тесты покрывают чистую логику (`control.py`, `schedule.py`, `entry.py`) и не
требуют Home Assistant. `strings.json` и `translations/en.json` должны
совпадать (проверяется в CI).
